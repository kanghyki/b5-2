# Mini Git

Git의 커밋 구조를 재현한 프로그램입니다. 브랜치를 만들어 커밋을 쌓고, 커밋 그래프를 탐색하고, 메시지와 작성자로 커밋을 검색할 수 있습니다. 두 텍스트 파일을 줄 단위로 비교하는 `DIFF`도 제공합니다. 파일 내용은 추적하지 않고 커밋 메타데이터만 다룹니다.

같은 명령을 두 가지 방식으로 실행할 수 있습니다.

- **REPL:** `mini-git>` 프롬프트에서 명령을 이어서 입력합니다. 저장소는 메모리에만 있어 종료하면 사라집니다.
- **CLI:** 셸에서 명령 하나를 실행하고 끝납니다. 저장소는 `.minigit/` 디렉터리에 저장되어 다음 실행에서 이어집니다.

## 실행

Python 3.10 이상이 필요하고, 별도로 설치할 패키지는 없습니다.

```bash
python main.py                      # REPL, 환경에 따라 python3 main.py
python main.py <command> [args...]  # CLI, 예: python main.py commit "Add login feature"
python -m unittest                  # 테스트
```

## 명령어

명령어 이름은 대소문자를 구분하지 않습니다. 공백이 있는 문자열은 따옴표로 감쌉니다. CLI에서는 셸이 따옴표를 처리하므로, 셸 규칙대로 감싸면 됩니다.

| 명령어 | 동작 |
| --- | --- |
| `INIT <user_name>` | 저장소를 초기화하고 `main` 브랜치와 사용자를 설정 |
| `BRANCH <branch_name>` | 현재 커밋을 가리키는 브랜치 생성 |
| `SWITCH <branch_name>` | HEAD를 지정한 브랜치로 이동 |
| `COMMIT <message>` | 현재 HEAD를 부모로 하는 커밋 생성 |
| `LOG` | 모든 커밋을 부모가 먼저 오는 순서로 출력 |
| `LOG --sort-by=date\|author` | 시각 또는 작성자 오름차순으로 출력 |
| `PATH <commit1> <commit2>` | 두 커밋 사이의 최단 경로 출력, 없으면 `No path` |
| `ANCESTORS <commit_hash>` | 커밋의 모든 조상 출력 |
| `SEARCH <keyword>` | 키워드가 메시지에 들어 있는 커밋 출력 |
| `SEARCH --author=<name>` | 해당 작성자의 커밋 출력 |
| `DIFF <file1> <file2>` | 두 텍스트 파일을 줄 단위로 비교해 추가·삭제·공통 줄 출력 |
| `exit`, `quit` | REPL 종료 |

오류는 `Invalid args`, `Unknown branch: <name>`, `Unknown commit: <hash>`, `Branch already exists: <name>`, `Unknown command: <name>`, `Repository not initialized`, `Cannot read file: <path>`로 출력합니다. CLI에서는 이 밖에 저장 파일을 읽거나 쓸 수 없을 때 `Corrupted repository: <path>`, `Cannot write repository: <path>`를 출력합니다.

```text
mini-git> init "Alice"
Initialized repository.
Current branch: main
Current user: Alice
mini-git> commit "Initial commit"
[main e3779b1] Initial commit
mini-git> branch feature
Created branch: feature
mini-git> switch feature
Switched to branch: feature
mini-git> commit "Add login feature"
[feature c6ef362] Add login feature
mini-git> path e3779b1 c6ef362
Path: e3779b1 -> c6ef362
mini-git> search "login"
Found 1 commit:
- c6ef362: Add login feature
```

## 동작 규칙

- **INIT 재실행:** 이력과 현재 브랜치를 유지한 채 사용자만 바꿉니다. 사용자를 바꾸는 유일한 방법이므로, 작성자가 여러 명인 이력은 이 방식으로 만듭니다.
- **커밋이 없을 때의 BRANCH:** 빈 브랜치를 만듭니다. 그 브랜치의 첫 커밋은 부모가 없는 별도의 뿌리 커밋이 되고, 이렇게 연결되지 않은 커밋 사이에서 `PATH`는 `No path`를 출력합니다.
- **LOG 범위:** 현재 브랜치뿐 아니라 저장소의 모든 커밋을 출력합니다. 대괄호 안의 이름은 커밋이 만들어진 브랜치입니다.
- **정렬:** 오름차순입니다. 작성자는 대소문자 구분 없이 비교하고, 같은 값은 생성 순서를 유지합니다.
- **키워드 검색:** 공백으로 나눈 토큰 단위로 대소문자 구분 없이 일치시킵니다. `login`은 `relogin`이나 `login,`과 일치하지 않습니다. 공백이 있는 키워드는 토큰이 메시지에 연속으로 나타나는 커밋을 찾습니다.
- **작성자 검색:** 이름이 대소문자까지 정확히 같아야 합니다.
- **DIFF:** 저장소와 무관하게 동작하므로 `INIT` 없이도 쓸 수 있습니다. 상대 경로는 프로그램을 실행한 디렉터리 기준이고, 파일은 UTF-8 텍스트로 읽습니다. 공통 줄은 앞에 공백 두 칸, 삭제된 줄은 `- `, 추가된 줄은 `+ `를 붙이고, 마지막 줄에 개수를 요약합니다. 한 자리에서 줄이 바뀌면 삭제를 추가보다 먼저 보여 줍니다.

```text
mini-git> diff old.txt new.txt
--- old.txt
+++ new.txt
  keep
- old
+ new
  end
1 added, 1 deleted, 2 common
```

## CLI

인자를 주고 실행하면 명령 하나를 처리하고 끝납니다.

```bash
$ python main.py init "Alice"
Initialized repository.
Current branch: main
Current user: Alice
$ python main.py commit "Initial commit"
[main e3779b1] Initial commit
$ python main.py log
commit e3779b1 (Alice, 2026-11-11 10:00:00) [main]
    Initial commit
```

- **저장 위치:** 현재 디렉터리부터 상위로 올라가며 `.minigit/`을 찾습니다. 하위 디렉터리에서 실행해도 같은 저장소를 씁니다. 찾지 못하면 `INIT`이 현재 디렉터리에 새로 만들고, 다른 명령은 `Repository not initialized`를 출력합니다.
- **저장 시점:** `INIT`, `BRANCH`, `SWITCH`, `COMMIT`이 성공했을 때만 저장합니다. 조회 명령과 실패한 명령은 파일을 바꾸지 않습니다. `DIFF`는 저장소를 읽지도 만들지도 않습니다.
- **출력과 종료 코드:** 결과는 표준 출력에, 오류는 표준 오류에 쓰고 각각 종료 코드 0과 1로 끝납니다. `No path`, `No commits found` 같은 빈 결과도 정상 결과입니다.
- **인자:** 셸이 나눈 인자를 그대로 씁니다. 그래서 메시지에 따옴표가 들어 있어도 다시 나뉘지 않습니다.
- **REPL과의 관계:** REPL은 `.minigit/`을 읽거나 쓰지 않습니다. 두 방식은 같은 명령 실행기를 쓰므로 명령의 동작과 출력은 같습니다.

## 구조

```text
main.py               엔트리 포인트, 인자 유무로 REPL과 CLI 선택
minigit/graph.py      커밋 노드와 커밋 그래프
minigit/traversal.py  위상 정렬, 조상 탐색, 최단 경로
minigit/sorting.py    병합 정렬
minigit/index.py      역색인
minigit/diff.py       줄 단위 diff(LCS)
minigit/repository.py 브랜치, HEAD, 커밋 생성, 검색
minigit/storage.py    저장소 상태를 파일로 저장하고 불러오기
minigit/commands.py   명령 실행과 출력 형식(REPL과 CLI 공용)

tests/                단위 테스트, REPL과 CLI 테스트
```

## 설계

아래에서 V는 커밋 수, E는 부모-자식 간선 수입니다.

### 커밋 그래프가 DAG인 이유

커밋은 부모를 가리키고, 한 번 만들어지면 바뀌지 않습니다. 부모는 항상 이미 존재하는 커밋이므로 간선은 나중 커밋에서 먼저 만들어진 커밋으로만 향합니다. 따라서 어떤 커밋도 자기 자신으로 돌아올 수 없어 순환이 생기지 않습니다. 또한 브랜치가 갈라지면 한 부모에 자식이 여럿 생기고, 병합 커밋은 부모를 둘 이상 가질 수 있으므로 단순한 리스트나 트리가 아닌 그래프로 표현합니다.

`CommitGraph`는 해시맵으로 커밋을 O(1)에 찾고, `add`에서 존재하지 않는 부모를 거부해 이 성질을 유지합니다. 해시는 카운터 값에 홀수를 곱해 2^28로 나눈 나머지입니다. 이 연산은 일대일 대응이므로 2^28 - 1개까지 충돌 없이 만들 수 있고, 그 이후에는 오류로 처리합니다.

### 부모가 먼저 나오는 로그

부모마다 자식이 여럿일 수 있어 단순히 최신순으로 나열하는 방식으로는 그래프의 선후 관계를 표현할 수 없습니다. 그래서 위상 정렬인 Kahn 알고리즘을 사용합니다. 커밋마다 아직 출력되지 않은 부모 수를 세고, 0이 된 커밋을 큐에서 꺼내 출력한 뒤 자식의 수를 1씩 줄입니다. 커밋은 모든 부모가 출력된 뒤에야 큐에 들어가므로 부모가 항상 먼저 나옵니다. 시간복잡도는 O(V+E)입니다.

### 최단 경로와 조상 탐색

간선 가중치가 모두 같으므로 BFS가 간선 수 기준 최단 거리를 보장합니다.

- **PATH:** 간선을 무방향으로 보고 목적지에서 BFS로 거리를 구합니다. 그다음 출발지에서 시작해 거리가 1 줄어드는 이웃 중 해시가 가장 작은 쪽을 고릅니다. 앞자리부터 가장 작은 값을 고르므로 최단 경로 중 사전순으로 가장 앞선 경로가 됩니다. 시간복잡도는 O(V+E)입니다.
- **ANCESTORS:** 부모 간선만 따라 BFS로 탐색합니다. 방문 집합이 있어 여러 경로로 닿는 조상도 한 번만 출력합니다. 시간복잡도는 O(V+E)입니다.

### 병합 정렬

| 평균 시간 | 최악 시간 | 추가 공간 | 안정 정렬 |
| --- | --- | --- | --- |
| O(n log n) | O(n log n) | O(n) | 예 |

입력 상태와 상관없이 최악에도 O(n log n)을 보장하고, 같은 값의 순서를 유지하므로 동률인 커밋을 생성 순서대로 보여 줄 수 있습니다. `key` 함수만 바꾸면 비교 기준을 바꿀 수 있어 날짜와 작성자 정렬이 같은 코드를 사용합니다.

### 역색인

모든 커밋을 순회하는 검색은 메시지를 전부 확인해야 하므로 커밋 수에 비례합니다. 역색인은 커밋을 만들 때 메시지 토큰과 작성자를 키로 해시 목록을 미리 저장합니다.

| 방식 | 단일 키워드 검색 | 비고 |
| --- | --- | --- |
| 전체 순회 | O(V × L) | L은 메시지 평균 길이 |
| 역색인 | O(K) | K는 일치하는 커밋 수 |

검색 비용을 커밋 수가 아닌 결과 수에 비례하게 만드는 대신, 커밋을 만들 때 토큰 수만큼의 색인 갱신 비용과 추가 메모리를 사용합니다. 공백이 있는 키워드는 각 토큰의 해시 목록을 교집합으로 좁힌 뒤, 남은 후보에서만 토큰이 연속으로 나타나는지 확인합니다.

### 줄 단위 diff

두 파일의 차이를 가장 적은 줄로 보여 주려면 바꾸지 않아도 되는 줄, 즉 두 파일에 같은 순서로 나타나는 줄을 최대한 많이 남겨야 합니다. 이것이 최장 공통 부분 수열(LCS) 문제입니다. LCS에 든 줄은 공통 줄, 첫 파일에만 남은 줄은 삭제, 둘째 파일에만 남은 줄은 추가가 됩니다.

`lcs[i][j]`를 `old[i:]`와 `new[j:]`의 LCS 길이로 두고 표의 끝에서부터 채웁니다. 그다음 앞에서부터 따라가며 두 줄이 같으면 공통으로 내보내고, 다르면 LCS가 더 긴 쪽으로 이동합니다. 두 방향의 값이 같으면 삭제를 택하므로 바뀐 줄은 삭제가 추가보다 먼저 나옵니다.

| 시간 | 추가 공간 |
| --- | --- |
| O(n × m) | O(n × m) |

n, m은 두 파일의 줄 수입니다. 보통 수정은 파일 일부에만 있으므로 표를 만들기 전에 앞뒤의 같은 줄을 떼어 내고, 남은 구간만 표로 계산합니다. 실제 Git은 바뀐 줄 수 D에 대해 O((n + m) × D)인 Myers 알고리즘을 쓰지만, 이 프로젝트는 파일 크기가 작다고 보고 구현이 단순한 LCS 표를 택했습니다.

### REPL과 CLI의 분리

두 방식은 입력을 받는 방법과 저장소가 사는 기간만 다릅니다. 그래서 명령을 처리하는 부분을 `CommandRunner` 하나로 모으고, 두 인터페이스는 그 앞뒤만 맡습니다.

| | REPL | CLI |
| --- | --- | --- |
| 입력 | 한 줄을 `shlex`로 토큰화 | 셸이 나눈 인자를 그대로 사용 |
| 저장소 | 세션 동안 메모리에 유지 | 실행마다 `.minigit/state.json`에서 불러오고 저장 |
| 오류 | 메시지를 출력하고 다음 입력을 받음 | 표준 오류에 쓰고 종료 코드 1 |

CLI는 실행할 때마다 프로세스가 새로 뜨므로 상태를 파일에 남겨야 합니다. 저장 파일에는 커밋을 생성 순서대로, 브랜치, HEAD, 사용자, 해시 카운터를 기록합니다.

- **커밋 순서:** `LOG`의 위상 정렬과 정렬의 동률 처리는 커밋이 그래프에 들어간 순서를 따릅니다. 불러올 때 같은 순서로 다시 넣으므로 결과가 저장 전과 같습니다.
- **해시 카운터:** 해시는 카운터에서 만들어지므로, 카운터를 저장하지 않으면 다음 실행에서 같은 해시가 다시 나옵니다. 카운터를 이어 받아 저장소 전체에서 해시가 유일하게 유지됩니다.
- **역색인:** 커밋에서 다시 만들 수 있으므로 저장하지 않습니다. 불러올 때 커밋을 다시 넣으면서 함께 만들어지고, 비용은 전체 토큰 수에 비례합니다.
- **안전한 저장:** 같은 디렉터리의 임시 파일에 모두 쓴 뒤 이름을 바꿔 교체합니다. 쓰는 도중에 멈춰도 기존 파일이 깨지지 않습니다. 다만 잠금은 없으므로 여러 프로세스가 동시에 쓰면 마지막으로 저장한 쪽만 남습니다.
